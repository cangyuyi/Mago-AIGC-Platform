# 🧙‍♂️ Mago Agent 创意平台 — 详细执行计划

> **文档版本**：v1.0  
> **创建日期**：2026-09-07  
> **产品定位**：Mago 上游的 AI 创意 Agent 大脑——从热点发现/选题策划 → 脚本分镜 → 文生图/文生视频专业提示词包的端到端自动化平台，输出可直接粘贴到 Mago（或任何生图/生视频平台）使用的结构化提示词。  
> **核心价值**：用户不再需要懂 Prompt 工程、不再需要自己想选题写脚本，Agent 帮你完成"想什么→写什么→怎么描述"全链路，用户只需要做最终决策和生成。

---

## 一、产品边界定义

### 1.1 In Scope（做什么）

| 能力域 | 具体范围 |
|:---|:---|
| 热点情报 | 多平台热点聚合、爆款内容拆解、选题推荐、趋势预测 |
| 创意策划 | 选题生成、脚本写作、分镜设计、人设/风格定义 |
| 提示词工程 | 文生图提示词、文生视频提示词、跨镜头一致性提示词、负向词、参数建议 |
| 模型适配 | 针对不同生图/生视频模型（Midjourney/SD/Flux/Kling/Runway/Sora/Vidu/可灵等）输出适配版本 |
| 资产管理 | 角色卡、风格LoRA映射、品牌视觉规范、历史项目复用 |
| 人机协作 | 人工审核/修改/选择节点，Agent 根据反馈迭代优化 |
| 一键输出 | 提示词包一键复制/导出/直接推送到 Mago 平台执行 |

### 1.2 Out of Scope（不做什么，Mago已有）

| 能力域 | 说明 |
|:---|:---|
| 图片/视频实际生成 | 由 Mago 平台或第三方平台完成 |
| 视频剪辑/后期 | 不在本期范围 |
| 视频发布/分发 | 不在本期范围 |
| 算力调度/模型路由 | Mago 已有能力 |

### 1.3 核心用户旅程（Happy Path）

```
用户输入（一句话/一个赛道/一个链接）
        │
        ▼
┌───────────────────┐
│  1. 选题策划 Agent │ ← 热点雷达+爆款库+用户画像
│  输出：选题卡片×N   │
└───────┬───────────┘
        │ 用户选择/修改选题
        ▼
┌───────────────────┐
│  2. 脚本分镜 Agent │ ← 脚本专家团+分镜知识库
│  输出：分镜脚本     │
└───────┬───────────┘
        │ 用户审核/调整分镜
        ▼
┌───────────────────┐
│  3. 角色风格 Agent │ ← 角色卡+风格库+品牌规范
│  输出：角色设定+风格 │
└───────┬───────────┘
        │ 用户确认/修改形象
        ▼
┌───────────────────┐
│  4. 提示词生成 Agent│ ← 模型模板库+Prompt工程SOP
│  输出：提示词包     │
└───────┬───────────┘
        │ 用户微调/选择模型版本
        ▼
┌───────────────────┐
│  5. 输出&推送      │ → 复制/导出/Mago一键生成
│  完成交付          │
└───────────────────┘
```

## 二、系统模块详细设计（7大板块，35个子模块）

### 板块一：热点情报中心（Trend Intelligence）

#### 1.1 多平台热点爬取引擎
- **功能描述**：实时/准实时爬取主流平台热点数据
- **覆盖平台**：
  - 短视频：抖音热榜/抖音灵感、快手热榜、视频号热门、小红书热门笔记、B站热门
  - 海外：TikTok Trending、YouTube Shorts Trending、Instagram Reels
  - 图文资讯：微博热搜、百度热搜、知乎热榜、头条热榜
  - AIGC垂直：Liblib/Civitai热门模型、即梦/可灵社区热门作品、Runway Showcase
- **数据维度**：话题标题、热度值、增长率、分类标签、相关视频/笔记链接、发布时间、互动数据（赞/评/转/完播率估算）
- **采集频率**：核心平台每15分钟一次，次要平台每1小时一次
- **反爬策略**：代理池轮换、请求频率控制、Cookie池、Headless浏览器兜底
- **去重与聚合**：跨平台同话题聚合（基于语义相似度+关键词匹配），话题生命周期追踪
- **交付物**：爬虫服务模块、代理管理模块、数据清洗Pipeline

#### 1.2 爆款视频内容拆解引擎
- **功能描述**：输入一条爆款视频URL或文件，自动多维度拆解
- **拆解维度**：
  - **元数据层**：时长、分辨率、发布时间、账号信息、标签、音乐
  - **结构层**：镜头分割（基于场景切换检测）、每个镜头时长、镜头顺序、转场类型
  - **视觉层**：每个关键帧的景别（特写/近景/中景/全景/远景）、色调、光影、构图风格、主体检测
  - **文案层**：语音转文字（ASR）、字幕提取、口播文案全文、文案结构（钩子/正文/CTA）
  - **听觉层**：BGM识别（曲名/情绪/BPM）、音效类型、语音情绪
  - **节奏层**：节奏曲线（镜头切换频率随时间变化）、音乐节拍点、情绪曲线
  - **数据层**：互动数据、评论关键词、完播率估算
- **技术实现**：
  - 视频下载：yt-dlp + 各平台专用解析
  - 镜头分割：PySceneDetect + TransNetV2（深度学习镜头边界检测）
  - 关键帧提取与分析：GPT-4o/Gemini 2.5 Pro 多模态理解
  - ASR：Whisper-large-v3 / FunASR（中文优化）
  - BGM识别：ACRCloud API / Shazam API
  - 节拍检测：Librosa
- **输出格式**：结构化JSON爆款拆解报告 + 可视化节奏曲线图
- **交付物**：视频下载服务、镜头分割模块、多模态分析模块、ASR模块、爆款拆解报告模板

#### 1.3 热点趋势分析与预测
- **功能描述**：基于历史热点数据，做趋势分析与热度预测
- **能力点**：
  - 话题热度生命周期曲线（上升期/爆发期/衰退期）
  - 话题分类聚类（基于embedding做无监督聚类+人工标注映射）
  - 跨平台传播路径追踪
  - 上升期热点提前预警（增速>阈值自动推送）
  - 垂类赛道（电商/美妆/3C/美食/剧情/知识等）热点订阅
- **预测模型**：基于历史热度曲线的时序预测（Prophet/轻量LSTM），初期用规则+统计即可
- **交付物**：趋势分析看板、热点预警服务、分类标签体系

#### 1.4 选题推荐引擎
- **功能描述**：基于用户输入（赛道/账号/关键词/参考视频）+ 热点数据 + 历史爆款规律，推荐可执行的选题
- **输入方式**：
  - 自然语言描述："帮我想10个美妆带货短视频选题"
  - 选择赛道/垂类
  - 输入参考爆款视频URL（做风格迁移式选题）
  - 上传账号历史内容（分析账号风格）
- **推荐维度**：
  - 热度分（当前热度+上升趋势）
  - 竞争分（同选题创作者数量反向计分）
  - 适合度分（与用户账号定位/历史风格的匹配度）
  - 可执行性分（AI生成的可控性/可操作性）
- **选题卡片结构**：选题名称、一句话钩子、核心卖点/话题点、目标受众、建议时长、建议形式（口播/剧情/展示/混剪）、参考爆款链接、预期热度等级、风险提示
- **推荐数量**：每次输出10-20个选题卡片，按综合分排序
- **交付物**：选题推荐Agent、选题卡片模板、选题评分模型

### 板块二：脚本创作中心（Script Studio）

#### 2.1 多Agent脚本写作团
- **Agent角色设计**：
  - **创意总监Agent（Chief Creative）**：统筹全局，决定整体创意方向和调性，审核其他Agent的输出
  - **钩子专家Agent（Hook Specialist）**：专写前3秒钩子，研究上百种钩子套路（悬念式/冲突式/反常识式/痛点式/数字式/提问式/对比式）
  - **叙事编剧Agent（Storyteller）**：负责主体叙事结构，包含起承转合、情绪曲线、信息密度控制
  - **文案撰稿Agent（Copywriter）**：口播文案、字幕文案、标题、描述、标签
  - **转化专家Agent（Conversion Optimizer）**：CTA设计、种草逻辑、带货话术优化
  - **合规审查Agent（Compliance）**：广告法/平台规则/敏感词/版权风险前置审查
- **协作模式**：
  - 串行Pipeline：钩子→叙事→文案→转化→合规
  - Debate模式：对关键决策点（如钩子选择、叙事角度），多个Agent给出方案后辩论，创意总监裁决
  - Reflection模式：初稿完成后，自我审视+交叉审稿，迭代优化
- **交付物**：各Agent角色Prompt（宪法层+流程层+表达层）、Agent编排DAG、协作状态机

#### 2.2 脚本模板库
- **内置脚本模板类型**（初期30+套）：
  - 口播类：知识口播、好物推荐、行业揭秘、经验分享、观点输出
  - 剧情类：反转短剧、情感故事、职场剧、家庭剧、悬疑片段
  - 展示类：产品开箱、变装展示、美食制作、风景混剪、运动剪辑
  - 种草类：测评对比、教程攻略、避坑指南、清单推荐、沉浸式体验
  - 热点类：热点评论、梗模仿、BGM同款、挑战赛内容
  - 品牌类：品牌故事、TVC片段、产品大片、创始人IP
- **模板结构**：每个模板包含时长分布、镜头数量建议、每个镜头的功能定位、文案节奏、BGM情绪建议、参考案例
- **模板可配置**：用户可自定义模板、保存为团队模板
- **交付物**：30+脚本模板（结构化JSON格式）、模板编辑器UI

#### 2.3 分镜脚本生成引擎
- **功能描述**：将脚本自动转化为逐镜头的分镜脚本
- **分镜表字段**：
  | 字段 | 说明 |
  |:---|:---|
  | 镜号 | 顺序编号 |
  | 时长 | 建议时长（秒） |
  | 景别 | 特写/近景/中景/全景/远景/微距 |
  | 运镜 | 固定/推/拉/摇/移/跟/升/降/环绕/手持 |
  | 画面描述 | 场景、人物、动作、道具、环境（自然语言） |
  | 台词/旁白 | 对应的口播/字幕文字 |
  | 音效/BGM | 该镜头的音乐情绪、音效 |
  | 情绪标签 | 该镜头要传达的情绪（紧张/温暖/震撼/搞笑…） |
  | 参考图 | 可选：参考视觉风格的图片URL |
  | 转场 | 与下一镜头的转场方式 |
- **关键能力**：
  - 自动分配景别变化（避免连续同景别导致视觉疲劳）
  - 自动节奏设计（快节奏段镜头短、慢节奏段镜头长）
  - 与BGM节拍对齐（可选）
  - 支持手动编辑调整
- **交付物**：分镜生成Agent、分镜表数据结构、分镜编辑UI（表格视图+时间线视图）

#### 2.4 脚本质量评估
- **评估维度**：
  - 钩子强度：前3秒是否足够吸引人？（基于钩子套路库+爆款数据）
  - 节奏合理性：镜头时长分布是否符合该类视频的最佳实践？
  - 信息密度：是否太啰嗦/太稀疏？
  - 情绪曲线：是否有起伏？是否在合适位置设置高潮？
  - CTA有效性：结尾转化引导是否明确？
  - 合规性：是否有违规风险？
  - 生成可行性：脚本描述的画面AI能否实现？是否需要拆分/简化？
- **评分制**：每个维度1-10分，总分+改进建议
- **交付物**：脚本评估Agent、评分Prompt、改进建议生成逻辑

### 板块三：角色与风格管理中心（Character & Style）

#### 3.1 角色卡系统
- **功能描述**：管理视频中出现的人物/角色设定，确保跨镜头一致性
- **角色卡字段**：
  | 字段 | 说明 |
  |:---|:---|
  | 角色ID | 全局唯一标识 |
  | 角色名称 | 角色名/昵称 |
  | 性别/年龄 | 基础属性 |
  | 种族/面部特征 | 详细面部描述（用于提示词） |
  | 体型 | 身材描述 |
  | 发型/发色 | 头发细节 |
  | 服装风格 | 日常/特定场景的穿着描述 |
  | 标志性特征 | 痣/疤痕/配饰/眼镜等辨识度特征 |
  | 性格/气质 | 影响表情和姿态的关键词 |
  | 参考图 | 角色参考图（1-3张正面/侧面） |
  | FaceID/IP-Adapter权重 | 对应的一致性模型参数建议 |
  | 适用模型 | 该角色卡适配哪些生图/生视频模型 |
  | 专属提示词片段 | 自动拼接到每个涉及该角色的prompt中的固定描述段 |
- **角色卡创建方式**：
  - 文字描述创建：用户描述角色外貌，Agent补全专业细节
  - 参考图创建：上传照片，多模态模型提取描述+建议FaceID参数
  - 角色库选择：平台预置角色库（按风格/年龄/性别/职业分类）
- **角色一致性策略**：
  - 文生图：IP-Adapter FaceID / InstantID 参考图权重建议
  - 文生视频：首帧参考图+角色提示词片段+种子锁定策略
  - 跨镜头：在每个分镜prompt中固定嵌入角色描述段，使用相同seed区间
- **交付物**：角色卡数据模型、角色卡创建UI、角色卡库（预置50+角色）、一致性参数模板

#### 3.2 风格定义系统
- **风格类型**：
  - **视觉风格**：写实/电影感/日系/韩系/港风/赛博朋克/水彩/油画/二次元/3D渲染/像素风/黏土风等
  - **光影风格**：自然光/伦勃朗光/霓虹光/逆光/黄金小时/阴天柔光/戏剧光等
  - **色调风格**：暖色调/冷色调/高饱和/低饱和/胶片色/莫兰迪/青橙色调等
  - **镜头风格**：浅景深/广角/微距/航拍/鱼眼/变形宽银幕/复古镜头等
  - **导演/电影风格**：预置名导风格包（诺兰/维伦纽瓦/王家卫/宫崎骏/韦斯·安德森等）
- **风格卡字段**：风格名称、风格描述（自然语言）、正向提示词片段、负向提示词片段、推荐参数（采样器/CFG/步数等）、参考调色LUT建议、适用模型、示例图
- **风格组合**：支持多风格叠加（如"电影感+赛博朋克+青橙色调"），Agent自动处理风格冲突/融合
- **品牌风格包**：企业用户可定义品牌视觉规范（品牌色、字体风格、画面调性、代言人形象），所有输出自动遵循品牌规范
- **交付物**：风格卡数据模型、风格库（预置100+风格）、风格组合引擎、品牌风格包管理

#### 3.3 场景/道具库
- **预置场景分类**：室内（家居/办公室/餐厅/商场/教室/医院…）、室外（城市/自然/海边/山/街道/乡村…）、虚构场景（太空/奇幻/未来/古代…）
- **预置道具分类**：电子产品/家居用品/交通工具/食物/服饰/武器/魔法道具…
- **每个场景/道具条目**：名称、分类、描述关键词、适用风格、提示词片段、参考图
- **用户自定义**：可上传自定义场景/道具描述及参考图
- **交付物**：场景库/道具库（预置200+条目）、搜索与推荐UI

### 板块四：提示词生成引擎（Prompt Engine）⭐ 核心模块

#### 4.1 多模型提示词模板系统
- **设计原则**：不同模型的提示词语法、偏好词、有效权重差异巨大，**每个模型单独维护适配模板**，不追求一个Prompt打天下
- **首期适配模型清单**（含每个模型的模板特性）：

  | 平台 | 模型 | 提示词特点 |
  |:---|:---|:---|
  | Midjourney | v6.1 / v7 / Niji 6 | 短句+逗号分隔，权重用::，支持--ar/--s/--cref/--sref等参数，偏好艺术/风格化词 |
  | Stable Diffusion | SDXL / SD3.5 | 标签式提示词（danbooru标签体系+自然语言混合），权重用()/[]，需要Embedding/LoRA触发词，负向词极其重要 |
  | Flux | Flux.1 [schnell/dev] | 偏好自然语言描述，对长prompt理解好，不需要大量负向词，支持细节描述 |
  | 可灵(Kling) | Kling 3.0 | 中文提示词效果好，偏好动作+场景+镜头语言描述，支持首尾帧、运动笔刷 |
  | 即梦 | Jimeng | 中文原生，偏好自然语言+风格描述，支持参考图/角色参考 |
  | Runway | Gen-3 Alpha / Gen-4 | 英文提示词优，描述要具体到subject+action+environment+style+camera，镜头运动描述重要 |
  | Pika | Pika 2.0 | 简洁描述+修改区域，支持inpainting式修改，动作描述简洁有力 |
  | Vidu | Vidu 1.5/2.0 | 中英文皆可，偏好角色一致性描述+动作描述，支持参考图+文本 |

#### 4.2 文生图提示词生成Agent
- **输入**：分镜单镜头信息 + 角色卡 + 风格卡 + 选定模型
- **生成逻辑**（按模型模板组装）：
  1. **主体描述段**：从角色卡提取角色固定描述 + 该镜头中角色的动作/表情/服装/姿态
  2. **场景环境段**：从场景库提取场景描述 + 该镜头的时间/天气/氛围/道具
  3. **构图镜头段**：景别、运镜、视角、景深、镜头类型
  4. **光影色调段**：光源类型、光线方向、色调、氛围光
  5. **画质风格段**：从风格卡提取风格词 + 画质boost词 + 分辨率要求
  6. **LoRA/Embedding触发词**：根据风格和选定模型自动建议需要加载的LoRA及权重
  7. **负向词段**：通用负向词库 + 场景特定负向词 + 模型特定负向词
  8. **参数段**：推荐采样器、采样步数、CFG Scale、Seed策略、尺寸
- **特殊处理**：
  - 系列图一致性：同一场景/角色的多个镜头，固定使用相同的核心描述段+风格段，仅变化动作/表情/景别
  - Seed锁定策略：为同一角色/场景建议固定seed范围或seed值
  - ControlNet建议：如果该镜头需要精确构图（如产品摆放），建议开启ControlNet类型及参考图
- **输出格式**：
  ```
  === 【镜号3】可灵3.0 文生图/首帧提示词 ===
  ▶ 正向提示词：
  一位25岁亚洲女性，黑色长发微卷，穿着白色丝质衬衫，
  坐在落地窗边的木质椅子上，手捧咖啡杯微笑看向窗外，
  窗外是雨天的城市街景，玻璃上有水珠，室内暖黄色台灯光线，
  中景镜头，略微俯视，浅景深，柔和侧光，伦勃朗光，
  暖色调，电影感调色，柯达2383胶片质感，颗粒感，
  4K画质，超精细细节，皮肤质感自然，8K分辨率
  
  ▶ 负向提示词：
  模糊, 变形, 低画质, 多余手指, 丑陋, 水印, 文字,
  过度曝光, 死白, 噪点, 畸形手部, 不对称眼睛
  
  ▶ 推荐参数：
  比例：9:16 | 时长：5s | 运动幅度：中 | FPS：24
  参考图：角色卡正面照（IP-Adapter权重0.8）
  Seed建议：锁定 12345（同角色统一）
  ```
- **交付物**：文生图提示词生成Agent（核心Prompt+组装逻辑）、各模型模板配置、负向词库（通用+分场景）

#### 4.3 文生视频提示词生成Agent
- **输入**：分镜单镜头信息 + 角色卡 + 风格卡 + 首帧提示词（如有） + 选定视频模型
- **生成逻辑**：在文生图提示词基础上，增加视频特有的维度：
  1. **运动描述段**（核心差异）：
     - 主体运动：人物/物体的动作描述（行走、转身、抬手、微笑、奔跑…）要具体、有时序、有物理感
     - 镜头运动：推/拉/摇/移/跟/升/降/环绕/手持晃动，描述速度和方向
     - 环境运动：风吹动窗帘、雨滴下落、光线变化、烟雾飘动、人群走动等环境动态
     - 运动节奏：快慢结合、动静对比
  2. **时序连贯性段**：
     - 关键帧节点提示：在第几秒发生什么关键动作
     - 首帧/尾帧描述：如果模型支持首尾帧
  3. **物理真实感段**：重力、碰撞、布料运动、流体运动、光影变化的自然性描述
  4. **避免描述**：明确提示模型不要做什么（不要变形、不要闪烁、不要角色变脸）
- **视频Prompt结构（因模型而异）**：
  - Kling类（中文）：场景+人物+动作+镜头+氛围，一段完整中文描述，100-300字
  - Runway/Sora类（英文）：[Subject] [action/motion] in [environment], [camera movement], [lighting], [style], [quality]. 电影剧本式描述
  - Pika类：简洁短句，突出关键动作变化
- **运动笔刷/区域控制提示**（Kling/Pika支持）：建议哪些区域需要运动、运动方向
- **跨镜头连贯性建议**：
  - 同场景相邻镜头建议使用相同seed
  - 上一镜头尾帧作为下一镜头首帧
  - 角色描述段严格一致
  - 色调/光影段一致
- **输出格式**：每个镜头的完整视频提示词 + 首帧图提示词 + 参数建议 + 连贯性策略建议
- **交付物**：文生视频提示词生成Agent、运动描述词库、镜头运动模板库、跨镜头连贯性逻辑

#### 4.4 提示词优化与迭代Agent
- **功能描述**：用户对生成结果不满意时，Agent根据反馈自动优化提示词
- **优化场景**：
  - 结果不符合预期 → 用户用自然语言描述问题（"角色脸变了"/"画面太暗"/"动作不对"）→ Agent自动定位是哪个段落的问题，修改对应部分
  - 风格不对 → 自动调整风格词权重/替换风格词
  - 画质不满意 → 增强画质boost段/调整参数
  - 角色不一致 → 强化角色描述段/增加FaceID建议/调整参考图权重
  - AI幻觉/多余元素 → 加入负向词/修改描述减少歧义
- **迭代策略**：
  - 每次只改2-3个变量，避免大改
  - 记录每次迭代的修改点和效果反馈
  - 积累Bad Case→优化方案映射库（复用Mago已有Prompt SOP）
- **交付物**：提示词优化Agent、Bad Case归因逻辑、迭代修改记录系统

#### 4.5 提示词质量自动评分
- **评分维度**：
  - **完整性**：是否包含主体/动作/场景/镜头/光影/风格/画质各要素
  - **具体性**：描述是否具体可执行，而非笼统抽象
  - **模型适配度**：是否符合目标模型的提示词偏好和语法
  - **一致性风险**：是否存在角色/风格跨镜头不一致的隐患
  - **安全合规**：是否有敏感/违规/版权风险
  - **可行性**：AI模型是否能生成这个描述（过于复杂的物理交互/文字/多人精确互动等需要标注风险）
- **评分输出**：总分100分 + 各维度得分 + 具体改进建议
- **交付物**：提示词评分Agent、评分标准Prompt、改进建议生成

### 板块六：人机协作与交互（Human-in-the-Loop）

#### 6.1 Agent对话式交互
- **自然语言驱动**：用户全程可以用自然语言和Agent对话
  - "帮我把这个选题改成更适合95后的语气"
  - "第3镜的光线改成黄昏逆光"
  - "把女主的头发改成短发，发色偏红"
  - "整体风格换成王家卫式的港风"
  - "这套提示词帮我适配Runway Gen-4版本"
- **上下文记忆**：Agent理解当前项目上下文，不需要每次重复
- **追问澄清**：信息不足时Agent主动提问（"女主角的年龄大约多大？""视频是竖屏还是横屏？"）
- **交付物**：对话引擎、上下文管理、追问逻辑

#### 6.2 关键节点人工审核
- **审核节点设计**：
  1. **选题审核**：Agent推荐选题 → 用户选择/修改/补充
  2. **脚本审核**：Agent生成脚本 → 用户编辑/确认
  3. **角色审核**：Agent生成角色描述 → 用户确认/上传参考图/修改
  4. **风格审核**：Agent推荐风格 → 用户选择/调整/上传参考图
  5. **分镜审核**：Agent生成分镜 → 用户逐镜头编辑/调整
  6. **提示词审核**：Agent生成提示词 → 用户微调/一键复制
- **审核模式**：
  - **快速模式**：跳过中间审核，一键端到端生成提示词包，适合熟练用户/批量生产
  - **精细模式**：每个节点人工确认，适合精品内容
  - **混合模式**：默认关键节点审核，其他自动通过
- **交付物**：审核流程引擎、节点状态管理、快速/精细模式切换

#### 6.3 可视化工作流编辑器
- **功能描述**：可视化展示从选题到提示词的完整Pipeline
- **视图**：
  - **卡片流视图**：选题卡→脚本卡→分镜卡→角色卡→提示词卡，线性流
  - **分镜表格视图**：表格形式展示所有镜头，方便批量编辑
  - **提示词对比视图**：不同模型版本的提示词并排对比
- **拖拽排序**：分镜支持拖拽调整顺序
- **一键重生成**：对任意节点点击"重新生成"，下游节点自动联动更新
- **交付物**：工作流编辑器前端、节点联动更新逻辑

#### 6.4 提示词预览与一键导出
- **导出格式**：
  - 一键复制（单镜头/全部镜头）
  - JSON格式导出（结构化数据，方便程序调用）
  - CSV/Excel导出（适合批量管理）
  - Markdown格式导出（适合文档归档）
  - **直接推送Mago**：通过Mago API将提示词包+参数直接推送到Mago创建生成任务（核心集成点）
- **Mago集成方案**：
  - 调用Mago的API，将每个分镜的提示词+参数+参考图创建为Mago任务
  - 支持批量提交（一键提交所有镜头）
  - 获取Mago的生成结果回调，在Agent平台展示
  - 生成不满意时，一键触发提示词优化Agent重新生成提示词再次提交
- **交付物**：导出模块、Mago API集成、结果回调展示

### 板块七：平台底座与基础设施（Platform Foundation）

#### 7.1 Agent编排引擎
- **编排框架**：基于 LangGraph 做核心编排
- **能力要求**：
  - DAG工作流定义（YAML/JSON配置各Agent节点和流转逻辑）
  - 状态持久化（每个节点的输入/输出/状态持久化到DB，支持断点续跑）
  - Human-in-the-loop节点（暂停等待人工输入，超时处理）
  - 条件路由（根据审核结果走不同分支：通过→下一节点/修改→重新生成/拒绝→返回选题）
  - 并行执行（如：多个模型版本的提示词同时生成）
  - 错误重试与降级（Agent调用失败自动重试，LLM不可用时降级到模板）
  - 节点耗时/Token消耗/成本追踪
- **交付物**：Agent编排引擎、工作流定义规范、节点注册机制、监控看板

#### 7.2 LLM接入与模型路由
- **支持的LLM**：
  - 主力：GPT-4o / Claude 3.5 Sonnet / Gemini 2.5 Pro（复杂创意任务）
  - 轻量：GPT-4o-mini / Claude Haiku / DeepSeek-V3（简单任务/分类/提取，降本）
  - 国产备选：Qwen-Max / GLM-4 / Doubao-Pro（数据合规场景）
  - 多模态：GPT-4o / Gemini 2.5 Pro（视频/图片分析）
- **模型路由策略**：
  - 按任务类型路由：创意写作→GPT-4o/Claude，视频分析→Gemini，简单分类→Mini模型
  - 按成本路由：非核心任务用便宜模型
  - 按可用性路由：主模型故障自动切备
- **Prompt管理**：所有Agent的System Prompt版本化管理，支持灰度发布和A/B测试
- **交付物**：统一LLM网关、模型路由策略、Prompt版本管理、Token成本监控

#### 7.3 数据存储设计
- **数据库选型**：
  - **PostgreSQL**：核心业务数据（用户/项目/脚本/分镜/角色/提示词/版本）
  - **Redis**：缓存（热点数据/Session/限流/临时状态）
  - **Milvus/Qdrant**：向量数据库（爆款库embedding/知识库embedding/语义检索）
  - **MinIO/S3**：对象存储（参考图/角色照片/视频片段/导出文件）
  - **Elasticsearch**（可选）：全文检索（爆款库文本/知识库内容）
- **核心数据表设计**（概要）：
  - `users` / `organizations` / `memberships`
  - `projects` / `project_versions`
  - `topics`（选题）/ `topic_versions`
  - `scripts`（脚本）/ `script_versions`
  - `storyboards`（分镜）/ `storyboard_shots` / `storyboard_versions`
  - `characters`（角色卡）/ `character_ref_images`
  - `style_presets`（风格卡）
  - `prompt_packages`（提示词包）/ `prompts`（单条提示词）/ `prompt_versions`
  - `trend_topics`（热点）/ `trend_videos`（爆款视频）/ `video_analyses`（拆解结果）
  - `knowledge_entries`（知识条目）
  - `agent_runs`（Agent执行记录）/ `agent_run_steps`
  - `exports`（导出记录）/ `mago_tasks`（推送Mago任务）
- **交付物**：数据库Schema设计、Migration脚本、索引设计

#### 7.4 用户系统与权限
- **用户认证**：邮箱/手机号注册登录、OAuth（微信/Google/GitHub）
- **组织/团队**：支持创建组织，邀请成员，角色权限（Owner/Admin/Editor/Viewer）
- **配额管理**：按用户/组织设置LLM调用次数、项目数、存储容量

- **交付物**：Trace系统、Grafana监控面板、告警规则、日志收集

## 三、Agent详细规格说明书

### Agent 1：热点情报官（Trend Agent）

**职责**：热点发现、爆款拆解、选题推荐

**输入**：用户指定的平台/垂类/关键词/参考视频URL  
**输出**：热点列表、爆款拆解报告、选题卡片

**核心能力**：
- 调用热点爬取服务获取实时热点
- 调用视频下载+多模态分析服务做爆款拆解
- 基于爆款库做相似案例检索
- 分析热点与用户需求的匹配度
- 生成选题卡片（含完整的创意角度）

**使用模型**：Gemini 2.5 Pro（视频/图片理解）+ GPT-4o（创意生成）+ Embedding模型（检索）

---

### Agent 2：创意总监（Creative Director Agent）

**职责**：统筹创意方向，审核和裁决其他Agent的输出

**输入**：选题卡 + 用户偏好设置  
**输出**：创意简报（Creative Brief）——包含整体调性、目标受众、核心信息、情绪方向、参考风格、差异化策略

**核心能力**：
- 理解选题的核心传播点
- 确定视频的整体创意策略（搞笑/感动/震撼/种草/反转…）
- 分配各Agent的任务和约束条件
- 对脚本初稿做终审和修改决策
- 解决Agent之间的"意见分歧"

**使用模型**：GPT-4o / Claude 3.5 Sonnet

---

### Agent 3：脚本编剧团（Script Team Agents）

包含钩子专家、叙事编剧、文案撰稿、转化专家、合规审查五个子Agent（详见板块二）

**输入**：创意简报 + 选题卡 + 参考爆款  
**输出**：完整脚本（含钩子/正文/CTA）+ 合规审查报告

**协作流程**：
1. 钩子专家产出3个钩子方案 → 创意总监选1个
2. 叙事编剧基于钩子产出完整脚本
3. 文案撰稿优化口播/字幕
4. 转化专家加CTA
5. 合规审查做风险标注
6. 创意总监终审
7. 自检Reflection：脚本评估Agent打分，低于阈值自动优化

**使用模型**：GPT-4o / Claude 3.5 Sonnet（创意写作）+ GPT-4o-mini（合规检查/分类）

---

### Agent 4：分镜师（Storyboard Agent）

**职责**：脚本→分镜表的转化

**输入**：脚本 + 角色信息 + 风格参考  
**输出**：分镜表（结构化JSON，含镜号/时长/景别/运镜/画面/台词/音效/情绪）

**核心能力**：
- 合理分配镜头数量和时长（总时长符合短视频最佳实践）
- 为每段文案匹配对应的景别和运镜
- 设计景别变化节奏（不连续同景别）
- 描述画面时使用具体、可视觉化的语言（而非抽象概念）
- 标注每个镜头的情绪和氛围

**使用模型**：GPT-4o / Claude 3.5 Sonnet

---

### Agent 5：角色设计大师（Character Designer Agent）

**职责**：角色卡的创建和管理

**输入**：用户的文字描述/上传的参考照片/脚本中的角色需求  
**输出**：完整的角色卡（含提示词片段/一致性参数建议）

**核心能力**：
- 从照片中提取详细的面部/体型/服装描述
- 将模糊描述转化为专业视觉描述词
- 选择适合该角色和风格的FaceID/IP-Adapter参数
- 确保角色描述在不同模型下的适配
- 生成角色专属的固定提示词片段

**使用模型**：GPT-4o / Gemini 2.5 Pro（图片理解）

---

### Agent 6：风格指导（Style Director Agent）

**职责**：视觉风格的定义和提示词转化

**输入**：用户选择/上传的风格参考图/脚本情绪需求  
**输出**：风格卡（含正向/负向风格词片段/参数建议/LoRA建议）

**核心能力**：
- 从参考图中识别视觉风格/色调/光影/构图
- 根据脚本情绪推荐合适的视觉风格
- 组合多种风格并处理冲突
- 为不同模型适配风格表达
- 推荐需要搭配的LoRA/模型及参数

**使用模型**：GPT-4o / Gemini 2.5 Pro（图片理解）

---

### Agent 7：提示词工程师（Prompt Engineer Agent）⭐ 最核心

**职责**：将分镜+角色+风格转化为目标模型的专业提示词

**输入**：分镜表 + 角色卡 + 风格卡 + 目标模型ID  
**输出**：每个镜头的完整提示词包（正向词+负向词+参数+一致性策略）

**核心能力**：
- 严格按照目标模型的模板结构组装提示词
- 将画面描述翻译/转化为模型敏感的专业词汇
- 为视频生成添加精准的运动描述和镜头运动描述
- 处理跨镜头一致性（seed/角色段/风格段/首尾帧策略）
- 自动补充画质增强词和负向词
- 推荐最优参数组合
- 对不可行/高风险描述进行标注和建议简化

**子Agent**：
- 文生图提示词专家（Image Prompt Specialist）
- 文生视频提示词专家（Video Prompt Specialist）
- 模型适配专家（Model Adapter）——负责同一镜头跨模型转换
- 质量审查专家（QA Reviewer）——提示词自动评分+改进建议

**使用模型**：GPT-4o / Claude 3.5 Sonnet（主力），提示词优化时使用Reflection模式

---

### Agent 8：迭代优化师（Optimizer Agent）

**职责**：根据用户反馈优化提示词

**输入**：当前提示词 + 用户反馈（自然语言/不满意的生成结果图）  
**输出**：优化后的提示词 + 修改说明

**核心能力**：
- 理解用户自然语言反馈，定位问题所在段落
- 根据生成结果图分析问题原因（需要多模态能力）
- 精准修改对应部分，不影响其他段落
- 积累优化经验到Bad Case库

**使用模型**：GPT-4o（多模态分析+修改）

### 4.3 与Mago平台集成设计

```
┌────────────┐     API      ┌────────────┐
│  Mago Agent │ ───────────→ │  Mago 平台  │
│  创意平台   │   (推送任务)  │  生成平台   │
│            │ ←─────────── │            │
│            │  (结果回调)   │            │
└────────────┘              └────────────┘
      │                           │
      │ 共享用户体系/资产           │ 共享算力/模型
      ▼                           ▼
┌─────────────────────────────────────┐
│       共享基础设施                    │
│  用户/组织/计费/存储/监控/日志        │
└─────────────────────────────────────┘
```

**集成点**：
1. **SSO统一登录**：Agent平台复用Mago用户体系，或通过OAuth互通
2. **一键推送到Mago生成**：
   - API: `POST /api/v1/agent/export-to-mago`
   - 参数：project_id, shot_ids[], model_id, parameters_overrides
   - 逻辑：将每个分镜的prompt+负向词+参数+参考图（角色卡图片）创建为Mago生图/生视频任务
3. **生成结果回传**：Mago任务完成后回调Agent平台，展示生成结果
4. **资产互通**：Mago中已有的LoRA/模型/风格预设可以在Agent平台中选择
5. **计费打通**：Agent平台的LLM调用费用和Mago的生成费用统一账单

## 六、Prompt工程规范（所有Agent共用）

参考你已有的《Prompt工业化迭代SOP》，Agent System Prompt采用三层结构：

### 6.1 宪法层（Constitution）
- 角色定位与核心目标
- 不可违反的原则（如：不输出违法内容、不编造不存在的能力、提示词必须具体可执行）
- 输出格式硬性约束
- 安全合规底线

### 6.2 流程层（Process）
- 思考链路（Chain of Thought）：要求Agent按步骤推理
- 输入→处理→输出的标准流程
- 自检清单：输出前必须逐项检查
- 异常处理：信息不足时追问、不确定时标注置信度

### 6.3 表达层（Expression）
- 语言风格：中文、专业、简洁、无废话
- 词汇表：使用统一的专业术语（景别/运镜/光影术语见知识库）
- 示例：提供2-3个高质量Few-shot示例
- 格式：严格的JSON/Markdown输出模板

### 6.4 Prompt迭代SOP
- 所有Agent Prompt纳入版本管理（同已有SOP）
- 每个Agent维护固定测试集（20+case）
- 双周迭代：Bad Case收集→归因→Prompt优化→双盲测试→灰度→全量
- 优化目标：提示词可用率≥85%，用户无需修改即可使用率≥70%

## 七、质量保障体系

### 7.1 提示词质量评估标准

| 等级 | 标准 | 用户行为预期 |
|:---|:---|:---|
| A级（优秀） | 直接粘贴使用即可生成满意结果，无需修改 | 直接复制→生成 |
| B级（良好） | 结构完整、描述准确，需微调1-2处 | 微调后生成 |
| C级（可用） | 核心要素齐全，但需要补充细节或调整风格 | 中等修改后可用 |
| D级（不可用） | 结构缺失/描述模糊/模型不适配 | 需要大幅修改或重新生成 |

### 7.2 评估方法

1. **自动评分**：提示词评分Agent从6个维度自动打分（完整性/具体性/模型适配度/一致性风险/合规/可行性）
2. **人工评测**：每周抽取100条生成结果，Prompt工程师按A/B/C/D评级
3. **用户行为数据**：
   - 提示词复制率（生成后被复制的比例）
   - 编辑率（用户对提示词的修改频率和幅度）
   - 一次通过率（复制后直接推送到Mago未修改的比例）
   - 重生成率（用户点击重新生成的比例）
   - Mago生成成功率/满意度（对接Mago数据）
4. **Bad Case闭环**：所有C/D级Case纳入Bad Case库，归因→优化Prompt→复测→灰度上线

### 7.3 测试集建设

- 每个核心场景（电商带货/知识口播/好物推荐/美妆种草/剧情短剧/风景混剪/美食制作/品牌TVC）维护30组标准化测试输入
- 每组测试输入包含：用户原始输入 → 期望脚本要点 → 期望分镜结构 → 期望提示词关键要素
- 每次Prompt修改后必须全量通过测试集，不允许退化

## 九、风险与应对

| 风险 | 影响 | 应对策略 |
|:---|:---|:---|
| LLM输出质量不稳定，提示词忽好忽坏 | 核心体验问题 | 严格的输出格式约束（JSON Schema/Function Calling）、自检Reflection环节、评分Agent兜底、人工审核节点 |
| 视频模型API变更/提示词语法更新 | 模板失效 | 模板版本化管理、监控模型更新、新模型快速适配机制（目标<4小时/个） |
| 热点爬取被平台封禁 | 数据来源中断 | 多渠道数据源冗余（官方API+第三方数据服务+页面爬取）、代理池、遵守robots.txt |
| 爆款视频拆解成本高（多模态API调用贵） | 运营成本 | 轻量模型做初筛、只对高价值视频做深度拆解、缓存复用、异步批量处理 |
| 角色一致性难以保证 | 视频质量问题 | 提示词层面优化+参数建议（FaceID/seed/参考图）+标注已知局限+给出多套方案 |
| 前端工作流编辑器复杂度高 | 开发延期 | MVP期先用表格+卡片流，React Flow可视化放到Phase 4 |
| LLM API成本失控 | 运营成本 | 轻量模型路由（简单任务用mini模型）、缓存（相似请求复用）、配额限制、成本监控告警 |
