# ADR-002: DAG工作流引擎自研决策
**状态**：生产环境已落地 **生效日期**：2026-05-20 **决策者**：产品/前后端架构师联合评审
---

## 背景
电商套图、漫剧分镜等企业级批量生产场景需要多步任务串联（如：分镜生成→人物一致性对齐→批量生图→智能精修→合成输出），单张零散生成完全无法满足企业批量生产效率要求，需要可视化工作流编排能力支撑。

## 可选方案评估
### 方案1：基于开源ComfyUI二次开发封装
- 实现方式：后端部署开源ComfyUI作为工作流执行引擎，前端做套壳适配和界面改造
- 优势：节点生态成熟，开源社区现成节点覆盖大部分生图基础能力
- 劣势：
  - 架构不适配SaaS多租户场景：ComfyUI为桌面端单用户设计，并发能力弱，多租户隔离、权限管控、计费对接需要深度改造，架构基因不匹配
  - 技术栈异构：ComfyUI后端基于Python，现有核心业务栈为Go+React，引入异构技术栈后运维、问题排查、二次开发成本极高，后续维护成本是原生栈的3倍以上
  - 定制化困难：核心调度逻辑与业务耦合深，全局人物一致性、断点续跑等业务特有需求需要侵入式修改源码，升级开源版本时冲突成本极高
  - 预估改造成本：3人周，后续每年维护成本约2人月
### 方案2：基于通用开源工作流引擎二次开发（n8n/Cadence）
- 实现方式：采用通用分布式工作流引擎编排AIGC任务，前端自研节点编辑界面
- 优势：通用调度能力成熟，自带重试、任务持久化能力
- 劣势：通用工作流引擎为通用业务流程设计，针对AIGC场景的大文件（图片/视频）流转、多模态数据传递支持差，前端可视化节点编辑器完全需要自研，整体适配成本4人周，且后续为AIGC场景做定制化修改时会受限于通用引擎的架构约束
### 方案3：自研轻量化分布式DAG工作流引擎
- 实现方式：前后端完全自研适配AIGC场景的轻量化DAG引擎，核心实现节点拖拽编排、多模态数据流转、分布式任务调度、断点续跑、全局特征一致性等业务必需能力，非核心能力按需迭代
- 优势：
  - 技术栈完全统一：后端Go+前端React，和现有业务栈100%打通，用户体系、计费、素材管理天然集成，没有异构技术栈维护成本
  - 场景高度适配：针对AIGC大文件流转、人物特征一致性、批量调度做原生优化，不需要适配通用引擎的冗余抽象
  - 并发性能优异：自研引擎针对AIGC任务特性做调度优化，同资源下并发能力是ComfyUI的5倍以上
  - 开发成本可控：核心能力开发周期2人周，后续维护成本极低
- 劣势：初期节点数量少于开源生态，需要逐步沉淀自有节点库

## 决策结果
选择**方案3：自研面向AIGC生产场景的轻量化分布式DAG工作流引擎**。

## 决策权衡依据
1.  **长期维护成本优先**：虽然开源方案短期看起来有现成能力，但异构技术栈和架构不匹配带来的长期维护成本是自研的2倍以上，项目生命周期超过1年时自研ROI显著更高
2.  **差异化竞争力构建**：自研引擎可以原生支持电商、漫剧场景的专属能力（如全局人物一致性、批量套图模板），这些能力是通用工作流/ComfyUI很难提供的，是产品的核心差异化壁垒
3.  **用户体验可控**：自研界面可以针对我们的目标用户（电商运营、漫剧创作者）做极简设计，不需要暴露ComfyUI复杂的参数选项，普通用户学习成本比ComfyUI低80%
4.  **多租户SaaS适配**：自研引擎原生支持多租户隔离、配额管控、计费统计，不需要额外改造就能满足企业级SaaS要求

## 落地效果验证
1.  核心能力2周按时上线，比开源二次开发方案提前1周交付
2.  同资源配置下并发调度能力是ComfyUI的5倍，支持千级并行工作流任务
3.  工作流用户ARPU值比普通生图用户高120%，企业用户留存率提升60%
4.  针对场景优化的全局一致性能力将多图人物符合率从32%提升到78%，成为漫剧客户选择我们的核心竞争力
5.  后续新增节点、新增业务功能迭代效率是二次开源方案的3倍以上，没有出现架构卡点
