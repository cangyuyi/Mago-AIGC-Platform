# ADR-003: 可观测体系建设路线决策
**状态**：生产环境已落地，持续迭代 **生效日期**：2026-06-10 **决策者**：产品/运维架构师联合评审
---

## 背景
随着业务规模增长，初期缺乏体系化可观测能力的问题逐渐暴露：故障依赖用户反馈发现，平均响应时间4小时+；成本核算依赖次日离线脚本跑数，曾出现上游API价格调整3天未发现，导致单月毛利下降8个点；问题排查需要跨多台机器捞日志，效率极低。需要建设适配AIGC业务特性的可观测体系。

## 可选方案评估
### 方案1：全量接入商业APM服务（Datadog/阿里云ARMS）
- 实现方式：全链路接入第三方商业可观测服务，开箱即用获得指标、日志、链路追踪能力
- 优势：功能全面，部署快，无需自行维护
- 劣势：
  - 成本极高：按AIGC业务的请求量级（日均千万级请求、大文件传输），年服务费预计4-5万元，且随着业务增长成本线性上升
  - 数据安全风险：业务请求数据、用户生成数据、成本数据全量上传第三方，存在商业敏感数据泄露风险
  - 定制化能力弱：商业APM为通用场景设计，AIGC场景特有的算力成本核算、毛利监控、模型渠道维度的指标统计需要大量定制开发，适配成本高
### 方案2：自建全栈开源可观测体系（Prometheus+Grafana+ELK+Jaeger）
- 实现方式：部署完整的开源可观测技术栈，实现指标、日志、链路追踪全能力
- 优势：功能全面，数据自主可控
- 劣势：
  - 运维成本极高：完整开源栈需要1名专职运维持续维护，小团队人力资源投入产出比低
  - 资源占用高：整套栈需要占用3-4台服务器，年资源成本2万+
  - 初期能力冗余：业务初期90%的运维场景只需要核心业务指标监控，全栈80%的高级功能初期用不上，属于过度建设
  - 预估建设周期：2人周，后续持续维护成本高
### 方案3：自研轻量化业务导向可观测体系
- 实现方式：优先建设业务最核心的可观测能力：结构化日志存储、核心业务指标（成功率、延迟、成本、毛利）实时看板、阈值告警、错误聚合；暂不建设代码级全链路追踪等非核心能力，后续按需迭代
- 优势：
  - 开发成本低：核心能力1人周即可上线，资源占用极低，几乎没有额外成本
  - 100%贴合业务：原生支持算力成本实时核算、毛利告警、渠道维度质量监控等AIGC特有指标，不需要适配改造
  - 数据完全自主可控，没有泄露风险
  - 迭代灵活：可根据业务需求随时新增指标和告警规则，不受第三方产品限制
- 劣势：初期不具备代码级全链路追踪能力，深层代码问题排查效率略低

## 决策结果
**分阶段建设可观测体系：v1阶段优先落地自研轻量化业务可观测核心能力，满足生产稳定性需求；v2阶段业务规模扩大后再按需补充代码级链路追踪能力，不盲目追求大而全的技术栈。**

## 决策权衡依据
1.  **需求优先级匹配**：业务发展初期90%的故障和问题都可以通过业务级指标（错误率、延迟、成本）定位，代码级链路追踪解决的是剩下10%的深层问题，优先解决主要矛盾
2.  **ROI最大化**：自研核心能力的投入仅为商业服务/全栈开源方案的1/5，上线后即可解决当前最痛的故障发现不及时、成本不可控问题，投入1周开发，当月即可通过减少成本浪费收回投入
3.  **架构演进原则**：可观测体系建设是长期过程，遵循"按需建设、逐本迭代"的原则，避免在业务验证阶段就投入大量资源建设复杂但使用率低的能力，避免过度设计
4.  **数据安全要求**：业务数据（成本、客户信息、生成内容）属于核心商业机密，自主可控是硬性要求，第三方商业服务无法满足数据安全要求

## 落地效果验证
1.  核心能力1周上线，快速解决了故障发现和成本监控的痛点
2.  故障平均发现时间从4.2小时缩短到1分钟，故障响应效率提升96%
3.  成本异常实时告警，每年减少无效算力浪费约4-5万元，远高于可观测体系的建设成本
4.  数据完全自主可控，没有第三方数据泄露风险
5.  后续随着团队扩张和业务复杂度提升，正在逐步补充全链路追踪能力，演进路线平滑，没有架构浪费
