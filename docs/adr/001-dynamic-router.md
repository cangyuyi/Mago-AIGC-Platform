# ADR-001: 动态加权多模型路由架构选型
**状态**：生产环境已落地 **生效日期**：2026-03-15 **决策者**：产品/后端架构师联合评审
---

## 背景
平台需要接入多家上游大模型/生图API服务商，构建多活容灾能力，解决单一服务商API稳定性差、成本波动大的问题，同时需要在成本、稳定性、延迟三者间找到最优平衡，支撑企业级SLA要求。

## 可选方案评估
### 方案1：硬编码固定路由
- 实现方式：配置文件硬编码每个模型对应的主服务商，故障时人工切换
- 优势：开发成本极低，可快速上线验证需求
- 劣势：故障响应滞后，切换需要发布版本，无法动态利用价格洼地，成本和稳定性都不可控，完全无法满足企业级SLA要求
### 方案2：基于成熟开源API网关二次开发（Kong/Apigee）
- 实现方式：部署开源API网关作为接入层，通过插件实现路由、限流、熔断能力
- 优势：通用功能成熟，自带基础限流、熔断能力
- 劣势：通用网关设计面向通用API场景，没有针对AIGC场景的成本/可用率/延迟三维加权调度逻辑，二次开发改造成本高（预估2人周）；网关本身过重，资源占用高，针对AIGC长连接、大文件传输场景适配不足，后续定制化迭代灵活性差
### 方案3：自研轻量化业务导向动态路由层
- 实现方式：在应用层自研轻量路由模块，实现基于可用率、延迟、成本三维动态加权调度，自带适配AIGC场景的健康检测、熔断、降级能力
- 优势：完全贴合业务场景需求，代码轻量化，资源占用低；路由策略可快速迭代，可针对企业租户特性做定制化路由规则；和现有业务栈（Go）完全打通，后续维护成本低；核心能力开发周期1人周
- 劣势：初期仅实现核心路由能力，通用网关的复杂管理功能需要逐步迭代

## 决策结果
选择**方案3：自研面向AIGC业务场景的动态加权路由层**。

## 决策权衡依据
1.  **ROI最优**：开源网关80%的通用功能AIGC场景根本用不上，二次开发的成本比自研核心能力还高，自研方案1周即可上线，投入产出比是开源方案的2倍以上
2.  **场景适配性**：通用网关无法原生支持"按成本权重调度、实时毛利校验、租户优先级路由"这类AIGC业务特有逻辑，自研可100%贴合业务需求
3.  **长期可维护性**：自研模块技术栈与现有后端栈完全统一（Go），不需要引入额外技术栈，后续功能迭代、问题排查效率更高，没有第三方依赖风险
4.  **演进路线清晰**：初期先实现核心路由/熔断/调度能力，后续根据业务需求逐步补充管理控制台、流量灰度等能力，符合"简单起步、逐步演进"的架构原则，避免一开始就引入过度复杂的重架构。

## 落地效果验证
1.  1周完成核心开发上线，比开源网关二次开发周期缩短50%
2.  上线后通过多渠道动态比价调度，单位算力成本比单一官方渠道下降38%
3.  配合自动熔断切流能力，平台可用性从91%提升到99.95%，达到企业级SLA标准
4.  后续新服务商接入仅需5分钟配置即可完成，不需要修改核心路由代码，扩展性极强
5.  路由资源占用仅为开源API网关的1/5，在高并发场景下延迟损耗<100ms，用户无感知
